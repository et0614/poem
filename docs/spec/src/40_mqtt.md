# MQTT の電文

この章は、PoEM Pod が PoEM Server へ送る MQTT の電文を定める。PoEM Server 以外の MQTT クライアントも、この章に従って電文を購読できる。

## トピックの体系

| トピック | 送る時機 | 内容 |
|---|---|---|
| poem/{pod}/pod/info | 全体の走査の前 | PoEM Pod の情報 |
| poem/{pod}/pod/diag | 1 秒ごと | PoEM Pod の I²C の診断 |
| poem/{pod}/node/{adr}/config | 全体の走査の後、子機の増設・交換のとき | 子機の固定の情報 |
| poem/{pod}/node/{adr}/data | 1 秒ごと | 計測値と状態 |
| poem/{pod}/node/{adr}/diag | 拡張ステータスが変わったとき | 子機の稼働の情報 |

- {pod} は PoEM Pod の ID とし、MAC アドレスを 16 進 12 桁 (英字は大文字) で表したもの (例: 0008DC030133) としなければならない。
- {adr} は子機の I²C アドレスとし、10 進で表さなければならない (例: 16)。
- 電文の本文は、UTF-8 の JSON としなければならない。

## 電文の形式

### pod/info

例: {"fw":"2.0.0","name":"3F 東","ip":"192.168.1.25"}

| キー | 型 | 内容 |
|---|---|---|
| fw | 文字列 | PoEM Pod のファームウェアの版 |
| name | 文字列 | PoEM Pod の名前 (空のこともある) |
| ip | 文字列 | PoEM Pod の IP アドレス |

### pod/diag

例: {"mst":1,"fail":1,"rcv":0,"to":0,"sf":0,"lost":1,"fm":0,"scn":15,"sdl":0,"scl":0}

| キー | 内容 |
|---|---|
| mst | I²C の周辺回路の現在の状態 (MSTATUS) |
| fail | I²C の転送の失敗の合計 (to + sf) |
| to | タイムアウトによる失敗の回数 |
| sf | 転送を開始できなかった失敗の回数 |
| fm | 失敗したときの MSTATUS |
| rcv | バスの固着からの復帰を実行した回数 |
| lost | 子機が読めなくなった回数 |
| scn | 走査を行った回数 |
| sdl、scl | SDA・SCL が Low に固着していると判断した回数 |

pod/diag は診断のためのものであり、PoEM Server はその内容を判断に使わない。

### node/config

例: {"uid":"4224605550008505013001404F0A1B2C","vendor":1,"model":771,"fw":"2.0.0","period":125,"name":"第2会議室 差圧","ch":[{"n":"DP","u":53,"t":0,"p":4,"f":0},{"n":"Temp","u":62,"t":0,"p":4,"f":2}]}

| キー | 型 | 内容 |
|---|---|---|
| uid | 文字列 | 子機の UID (16 B) を 16 進 32 桁 (大文字) で表したもの |
| vendor | 整数 | vendor_id |
| model | 整数 | model_id |
| fw | 文字列 | 子機のファームウェアの版 |
| period | 整数 | update_period_ms |
| name | 文字列 | 子機の名前 |
| ch | 配列 | チャネルの記述 (下表) |

| ch のキー | 内容 |
|---|---|
| n | チャネル名 |
| u | 単位 (BACnet Engineering Units) |
| t | 値の型 (0: float32、1: int32、2: uint32) |
| p | 有効桁数 (0: 既定) |
| f | フラグ (bit0: 積算値、bit1: 補助値) |

- PoEM Pod は、子機の名前と UID を、config を送るときに子機から読まなければならない。
- 名前に含まれる二重引用符・逆斜線・制御文字は、JSON の規則でエスケープしなければならない。

### node/data

例: {"sq":1234,"st":[0,0],"v":[23.45,51.2]}

| キー | 型 | 内容 |
|---|---|---|
| sq | 整数 | sample_seq。子機を読めなかったときは無い |
| st | 整数の配列 | チャネルごとの状態 (2.6.2 項の値) |
| v | 数値の配列 | チャネルごとの値。子機を読めなかったときは空 |

子機を読めなかったときは、{"st":[12,12],"v":[]} の形で送る。

- 整数の型のチャネルの値は、整数で書かなければならない。
- float32 の値は、有効桁数で丸めて書く。NaN と無限大は JSON に書けないので、0 と書き、状態を 7 にしなければならない。

### node/diag

例: {"up":3600,"rc":1,"err":0,"serr":0}

| キー | 内容 |
|---|---|
| up | 稼働時間 [s] (uptime_s) |
| rc | 直近の起動の要因 (reset_cause) |
| err | 上位機器との I²C の異常の回数 (err_i2c) |
| serr | センサとの通信の異常の回数 (err_sensor) |

## 配送の約束

- 電文は QoS 0 で送る。
- data は、毎秒、すべてのノードについて送らなければならない。子機を読めないときも送る。
- config は、全体の走査の後、子機が増えたとき、子機が交換されたときに送らなければならない。同じノードについて、config は data より先に送らなければならない。

解説: QoS 0 なので、電文が失われることがある。data が失われても、次の秒の data で回復する。config が失われると、PoEM Server はその子機を登録できず、次の全体の走査まで data を使えない。交換の後の config が失われた場合は、PoEM Server は前の子機の情報のまま新しい子機の値を受け取ってしまう。これらへの対策 (retain の利用、定期的な再送、data に短い ID を入れて照合する方法) は未決である (付録 F)。

## 時刻と順序

- 電文に時刻は入れない。時刻は PoEM Server が電文を受け取った時刻とする。
- sq (sample_seq) は、子機が新しい値を公開するたびに 1 増える。受け取る側は、sq が前回と同じなら値が更新されていないと判断してよい。sq が減ったら (65535 から 0 への一巡以外)、子機が再起動したと判断してよい。
