# OSL 共通レジスタ (子機の仕様)

この章は、OSL (OSL 共通レジスタ) の第 2 版 (v2) を定める。OSL は、I²C でつながるセンサ機器 (子機) のための汎用の共通レジスタの仕様であり、特定の製品やシステムに依存しない。子機は OSL を実装することで、自分の計測内容 (チャネルの名前・単位・値の型・状態) と個体の情報を、決まった番地で上位機器に提供する。上位機器は、子機の機種を知らなくても計測値を読める。

PoEM は OSL を使ったシステムの一つであり、この章の 2.8 節に PoEM の子機を例として示す。この章は、PoEM 以外の作り手が子機や上位機器を作るときにも、ほかの章を読まずに使えるように書いてある。

この章の規定は、次の 4 つの方針に基づく。

- 必須と任意を分ける。すべての子機が実装する「必須区画」と、必要な子機だけが実装する「任意区画」に分け、必須区画を番地の前半にまとめる。
- 未実装は 0 で表す。未実装の番地は 0 を返し、書き込みは無視する。0 は常に「未対応」または「既定値」を意味するように定義する。最小限の実装では、任意区画の位置や長さを知らなくてよい。
- 機種を知らなくても意味の分かるものだけを定める。補正係数や校正の手順など、機種の知識が要るものはユーザー領域に置く。
- 読み出す区画には、すべて CRC を付ける。

## 物理層と I²C の約束

### 電気的な条件

| 項目 | 規定 |
|---|---|
| 電源 | 3.3 V。上位機器から I²C の配線と一緒に供給する |
| コネクタ | Qwiic (JST SH 4 ピン、1.0 mm ピッチ)。ピンの並びは 1: GND、2: 3.3 V、3: SDA、4: SCL |
| プルアップ | 上位機器と、配線を分岐・延長する部品の側に置く。子機は SDA・SCL にプルアップ抵抗を持たないことを推奨する。持つ場合は、切り離せるようにしなければならない |
| 速度 | 100 kHz を前提とする。子機は 100 kHz で動作しなければならない |
| クロックストレッチ | 使ってもよい。ただし 1 回の伸長は 10 ms 以内とすることを推奨する |

- バスにつながるすべての機器は、Low を出すときに、プルアップの合成抵抗を流れる電流を吸い込めなければならない。I²C の規格の標準モードでは、3 mA を吸い込んだときに Low の電圧が 0.4 V 以下であることが求められる。3.3 V では、合成抵抗をおよそ 1 kΩ 以上とする。

解説: 延長ケーブルや子機の台数が増えると、バスの静電容量が増え、信号の立ち上がりがなまる。これを補うにはプルアップを強める (抵抗を小さくする) が、必要な強さは、配線の長さと台数で決まる。子機ごとにプルアップを持たせると、子機の台数に比例して合成抵抗が下がり、配線の状況と無関係に強くなりすぎる (例えば 5 kΩ の 64 台で約 78 Ω、Low のときに約 42 mA)。このため、プルアップは子機ではなく、配線を組む側 (上位機器、配線を分岐・延長する部品) に置き、配線に合わせて設定する。合成抵抗が小さすぎると、Low の電圧が十分に下がらず、受け手が Low を High と読み違える。

### アドレス

- I²C アドレスは 7 ビットで、0x08〜0x77 の範囲で使わなければならない。
- 工場出荷時のアドレスは 0x10 とすることを推奨する。作り手が別の値にしてもよい。
- 同じ I²C のバスにつなぐ子機のアドレスは、重ねてはならない。アドレスは、2.3.2 項の手順で変えられる。

解説: 工場出荷時のアドレスが同じ子機を同時に複数つなぐと、バスの上で衝突する。新しい子機は 1 台ずつつなぎ、アドレスを変えてから増設する。

### 番地の送り方とバイトの順序

| 項目 | 規定 |
|---|---|
| 番地 | 16 ビット。上位バイト、下位バイトの順に送る |
| データ | リトルエンディアン (CRC を含む) |
| 番地の単位 | 1 番地 = 1 B |
| 書き込み | S, アドレス+W, 番地上位, 番地下位, データ…, P |
| 読み出し | S, アドレス+W, 番地上位, 番地下位, Sr, アドレス+R, データ…, P。番地を書いて STOP し、改めて読む形にも対応しなければならない |
| 番地を送らない読み出し | S, アドレス+R, データ…, P。2.1.4 項の読み出し位置から返す |
| 自動加算 | 読み書きのたびに番地を 1 進める。区画をまたいでも続ける |
| 文字列 | UTF-8、NUL 終端 |

解説: 16 ビットの番地を持つ I²C 機器 (EEPROM や多くのセンサ) は、ほぼすべて番地を上位から送る。この順にしておけば、マイコンや OS の既存の関数 (STM32 の HAL_I2C_Mem_Read、Linux の EEPROM ドライバなど) でそのまま子機を読める。データは、多くのマイコンと PC の内部表現に合わせてリトルエンディアンとした。

### 読み出し位置の規則

子機は、STOP を受けたとき、次の表に従って読み出し位置を決めなければならない。

| 直前の通信 (その子機あて) | STOP の後の読み出し位置 |
|---|---|
| なし (電源投入直後) | 0x0000 |
| 読み出し | 0x0000 に戻す |
| データ付きの書き込み | 0x0000 に戻す |
| 番地 (2 B) だけの書き込み | 保持する |

解説: この規則により、上位機器は番地を送らずに読むだけで識別区画 (0x0000) を読める。相手が OSL の子機かどうかを、書き込みをせずに確かめられる (2.9.1 項)。番地を指定して書き込むと、8 ビットの番地を持つ機器は 2 B 目を「番地 0x00 へのデータ」と解釈し、レジスタを書き換えるおそれがある。読み出しだけなら、どの機器にも書き込みは起きない。番地だけの書き込みの後で位置を保つのは、「番地を書いて STOP し、改めて読む」形に対応するためである。

### 未実装の番地と書き込みの扱い

- 未実装・予約の番地は、読み出しで 0x00 を返さなければならない。書き込みは無視し、ACK を返さなければならない。
- 読み取り専用の番地への書き込みは無視し、ACK を返さなければならない。

## レジスタマップの全体

| 範囲 | 区画の種類 | 実装 | 内容 |
|---|---|---|---|
| 0x0000〜0x03FF | 必須区画 | すべての子機 | 識別、アドレス変更、名前、チャネル記述、POLL |
| 0x0400〜0x0FFF | 任意区画 | 必要な子機だけ | 拡張識別、拡張チャネル属性、拡張ステータス、コマンド |
| 0x1000〜0xFFFF | ユーザー領域 | 作り手の自由 | 機種ごとの設定・診断・独自の手順 |

区画は「変わらない情報から、毎回変わる情報へ」の順に並べてある (識別 → 名前 → チャネル記述 → POLL)。上位機器が読む順序と一致する。番地の一覧は付録 A に示す。

### CRC の付け方

- 読み出す区画は、すべてデータの直後に 2 B の CRC を持たなければならない。CRC の範囲は、その区画のデータ全体 (詰め物を含む) とする。
- 任意区画を実装しない子機は、その区画のデータも CRC もすべて 0 を返さなければならない。上位機器は「CRC を含めてすべて 0」を未実装と判断する。
- CRC の計算方法は 2.6.1 項に定める。

解説: この CRC は初期値が 0xFFFF なので、すべて 0 のデータの CRC は、どの長さでも 0 にならない。このため、「すべて 0」は正常なデータと区別できる。起動中に変わらない区画 (識別、チャネル記述、拡張識別、拡張チャネル属性) の CRC は、起動時に 1 回計算すればよい。

## 必須区画

すべての子機は、この節の区画を実装しなければならない。

| 番地 | 長さ | 区画 | 読み書き | 上位機器が読む時機 |
|---|---|---|---|---|
| 0x0000〜0x001F | 32 B | 識別 (CRC を含む) | 読み出し | 走査時 |
| 0x0020〜0x0021 | 2 B | アドレス変更 | 書き込み | 変更時 |
| 0x0022〜0x003F | 30 B | 予約 | — | — |
| 0x0040〜0x0081 | 66 B | 名前 (64 B と CRC) | 読み書き | 走査時、変更時 |
| 0x0082〜0x00FF | 126 B | 予約 | — | — |
| 0x0100〜 | 16×N+2 B | チャネル記述 (CRC を含む) | 読み出し | 走査時 |
| 0x0300〜 | 最大 84 B | POLL (CRC を含む) | 読み出し | 毎周期 |
| 0x0354〜0x03FF | — | 予約 (必須区画の将来の拡張) | — | — |

N はチャネル数 (1〜16) である。

### 識別 (0x0000〜0x001F)

| 番地 | 長さ | 名称 | 型 | 内容 |
|---|---|---|---|---|
| 0x0000 | 3 B | magic | char×3 | "OSL"。OSL の子機以外の機器と区別するための目印 |
| 0x0003 | 1 B | spec_version | uint8 | 仕様の版。この章の版は 2 |
| 0x0004 | 2 B | vendor_id | uint16 | 開発元の番号 (付録 B) |
| 0x0006 | 2 B | model_id | uint16 | 機種の番号 (付録 B)。上位バイトは計測の分類、下位バイトは通し番号 |
| 0x0008 | 3 B | fw_version | uint8×3 | ファームウェアの版 (major、minor、patch) |
| 0x000B | 1 B | channel_count | uint8 | チャネル数 N (1〜16) |
| 0x000C | 2 B | update_period_ms | uint16 | 新しい値を公開する周期 [ms] |
| 0x000E | 16 B | device_id | uint8×16 | 個体 ID (UID)。この項の後半に定める |
| 0x001E | 2 B | crc | uint16 | 0x0000〜0x001D の CRC |

- この区画は読み取り専用としなければならない。
- 中身は、起動してから電源を切るまで変えてはならない。

解説: この区画は、ファームウェアの定数とハードウェアに固有の値だけでできている。書き込みを許すと、誤った操作で機種の番号などが変わり、上位機器が機種を取り違えるおそれがある。変える必要のある情報は、別の区画 (アドレス変更、名前) で扱う。

#### device_id (UID) {.unnumbered}

device_id は、子機の個体を識別するための 16 B の値 (UID) である。値の作り方はこの仕様では定めず、次の条件を満たさなければならない。

| 条件 | 内容 |
|---|---|
| 一意性 | 同じシステムにつなぐ子機の間で重複しない |
| 不変性 | 再起動・電源の遮断・ファームウェアの更新で変わらない |
| 有効性 | 16 B がすべて 0 の値を使ってはならない (未設定を意味する) |
| 長さ | 16 B。元の値が短い場合は、後ろを 0x00 で埋める |

値の作り方の例を、推奨する順に示す。

1. マイコンの固有のシリアル番号。例: AVR DA/DB/DU の SIGROW.SERNUM0〜15 (16 B)、STM32 の UID (12 B)
2. 初回の起動時に作った乱数を不揮発メモリに保存した値。固有番号を持たないマイコンでも使える。書き込みのときに不揮発メモリを消去すると値が変わる点に注意する (AVR では EESAVE ヒューズで保護する)
3. ID チップや MAC アドレス (6〜8 B)

PoEM の子機は、1. の SIGROW.SERNUM を使う。

### アドレス変更 (0x0020〜0x0021)

| 番地 | 長さ | 名称 | 型 | 内容 |
|---|---|---|---|---|
| 0x0020 | 1 B | addr_key | uint8 | 0xA5 を書くと解錠する。STOP で必ず元に戻す |
| 0x0021 | 1 B | new_addr | uint8 | 新しい I²C アドレス (0x08〜0x77) |

- 上位機器は、番地 0x0020 から 0xA5 と新しいアドレスの 2 B を、1 回の通信で書かなければならない。
- 子機は、STOP を受けたときに鍵が 0xA5 で新しいアドレスが範囲内であれば、不揮発メモリに保存し、直ちに新しいアドレスに切り替えなければならない。再起動を要してはならない。
- 鍵が一致しない場合と、範囲外のアドレスの場合は、無視しなければならない。
- 読み出すと 0 を返す。

### 名前 (0x0040〜0x0081)

| 番地 | 長さ | 名称 | 型 | 読み書き | 内容 |
|---|---|---|---|---|---|
| 0x0040 | 64 B | name | char×64 | 読み書き | 利用者が個体に付ける呼び名。UTF-8、NUL 終端 |
| 0x0080 | 2 B | crc | uint16 | 読み出し | 0x0040〜0x007F の CRC |

- 名前の本文は最大 63 B (日本語で約 21 字) とし、残りを 0x00 で埋める。子機は、64 B 目を常に 0x00 にしなければならない。
- 書き込みに鍵は要らない。子機は、STOP を受けたら名前を不揮発メモリに保存し、CRC を計算し直さなければならない。
- 上位機器は、64 B を 1 回の通信でまとめて書くことを推奨する。
- 工場出荷時の名前は空 (先頭が 0x00) としなければならない。

解説: 名前は、機種名でもチャネル名でもなく、設置した個体の呼び名である (例: 「3F 第 2 会議室 天井 吹出口付近」)。子機の側に名前を持たせることで、子機をつなぎ替えても名前が失われない。アドレス変更のために不揮発メモリへの保存は最小限の実装でも要るので、名前を必須にしても作り手の負担は小さい。名前が空のとき、上位機器は代わりの表示 (機種名と I²C アドレスなど) を使う。

### チャネル記述 (0x0100〜)

チャネル i (0〜N−1) の記述は 0x0100 + 16×i に置き、N 個の記述の直後 (0x0100 + 16×N) に CRC を置く。

| 位置 | 長さ | 名称 | 型 | 内容 |
|---|---|---|---|---|
| +0 | 2 B | unit | uint16 | 単位。BACnet Engineering Units の値 (2.6.3 項) |
| +2 | 1 B | value_type | uint8 | 値の型。0: float32、1: int32、2: uint32 |
| +3 | 1 B | (予約) | — | 0 |
| +4 | 12 B | name | char×12 | チャネル名 (例: Temp)。UTF-8、NUL 終端。英数字を推奨する |
| N 個の後 | 2 B | crc | uint16 | 0x0100 から 16×N B の CRC |

- チャネルの数・順序・単位・型は、起動してから電源を切るまで変えてはならない。

解説: value_type は、大きな整数を正確に運ぶためにある。float32 の仮数は 24 ビットなので、16,777,216 を超える整数は 1 刻みで表せない。電力量計や水道メーターのパルスの積算はこれを超える。uint32 なら約 43 億まで正確に表せる。値の大きさは型によらず 4 B とした。型で大きさを変えると、値の位置の計算が子機と上位機器の双方に必要になり、誤りの元になる。0 が float32 なので、float だけを使う作り手は何も設定しなくてよい。

### POLL (0x0300〜)

| 位置 | 長さ | 名称 | 型 | 内容 |
|---|---|---|---|---|
| +0 | 2 B | sample_seq | uint16 | 新しい値を公開するたびに 1 増える。起動時は 0。65535 の次は 0 |
| +2 | 4×N B | value | 型はチャネル記述に従う | 計測値 |
| +2+4×N | N B | status | uint8 | チャネルごとの状態 (2.6.2 項) |
| N が奇数のとき | 1 B | (詰め物) | — | 0。CRC の位置を偶数にそろえる |
| 末尾 | 2 B | crc | uint16 | 先頭から直前までの CRC |

- 子機は、上位機器が番地 0x0300 を指定した時点で現在の値を写し取り (スナップショット)、続く読み出しでは写し取った値を返さなければならない。
- 子機は、新しい値を公開したときだけ sample_seq を 1 増やさなければならない。値を更新できなかった周期 (センサの異常など) には、sample_seq を増やしてはならない。

解説: スナップショットにより、読み出しの途中で値が更新されても、前半が古い値で後半が新しい値という壊れた値 (値の裂け) が起きない。sample_seq により、上位機器は新しい値かどうかと、子機の再起動 (65535 から 0 への一巡以外で値が減ったとき) を判断できる。再起動の確実な判定には、拡張ステータスの uptime_s を使う。

POLL の長さは 2 + 5×N + (N が奇数なら 1) + 2 B である。100 kHz での読み出しの時間の目安を示す。

| N | 長さ | 1 台あたり | 64 台の合計 |
|---|---|---|---|
| 2 | 14 B | 約 1.6 ms | 約 0.10 s |
| 8 | 44 B | 約 4.3 ms | 約 0.28 s |
| 16 | 84 B | 約 7.9 ms | 約 0.51 s |

## 任意区画

任意区画は、必要な子機だけが実装する。上位機器は、走査のときに拡張識別 (0x0400) を読む。CRC を含めてすべて 0 なら、任意区画の機能は無いものとして扱う。そうでなければ、capability に立っているビットの機能だけを使う。

| 番地 | 区画 | 読み書き | 上位機器が読む時機 |
|---|---|---|---|
| 0x0400〜0x0409 | 拡張識別 (CRC を含む) | 読み出し | 走査時 |
| 0x040A〜0x041F | 予約 | — | — |
| 0x0420〜 | 拡張チャネル属性 (4×N+2 B) | 読み出し | 走査時 |
| 0x0462〜0x047F | 予約 | — | — |
| 0x0480〜0x048B | 拡張ステータス (CRC を含む) | 読み出し | 低い頻度 (例: 10 秒ごと) |
| 0x048C〜0x04BF | 予約 | — | — |
| 0x04C0〜0x04C2 | コマンド | 書き込み | 操作時 |
| 0x04C3〜0x0FFF | 予約 (任意区画の将来の拡張) | — | — |

拡張チャネル属性・拡張ステータス・コマンドを実装する子機は、拡張識別を実装し、対応する capability のビットを立てなければならない。

### 拡張識別 (0x0400〜0x0409)

| 番地 | 長さ | 名称 | 型 | 内容 |
|---|---|---|---|---|
| 0x0400 | 2 B | capability | uint16 | 実装した任意機能のビット (下表) |
| 0x0402 | 1 B | hw_rev | uint8 | 基板の版 (0: 不明) |
| 0x0403 | 1 B | (予約) | — | 0 |
| 0x0404 | 2 B | avg_window_ms | uint16 | 平均化の時間幅 [ms] (0: 平均化なし)。値の時間的な意味を示す |
| 0x0406 | 2 B | warmup_ms | uint16 | 起動から値が有効になるまでの時間 [ms] (0: なし) |
| 0x0408 | 2 B | crc | uint16 | 0x0400〜0x0407 の CRC |

| capability のビット | 意味 |
|---|---|
| 0 | 拡張チャネル属性 (2.4.2 項) を実装する |
| 1 | 拡張ステータス (2.4.3 項) を実装する |
| 2 | リセットのコマンドを実装する |
| 3 | 識別のコマンドを実装する (LED など目に見える表示を持つ) |
| 4〜15 | 予約 (0) |

### 拡張チャネル属性 (0x0420〜)

チャネル i の属性は 0x0420 + 4×i に置き、N 個の直後 (0x0420 + 4×N) に CRC を置く。

| 位置 | 長さ | 名称 | 型 | 内容 |
|---|---|---|---|---|
| +0 | 1 B | precision | uint8 | 送信・表示の有効桁数 (0: 既定の 6 桁) |
| +1 | 1 B | flags | uint8 | bit0: 積算値 (一巡する)、bit1: 補助値 (センサの内部温度・生の電圧など)。ほかのビットは 0 |
| +2 | 2 B | (予約) | — | 0 |
| N 個の後 | 2 B | crc | uint16 | 0x0420 から 4×N B の CRC |

解説: precision は、上位機器が値を文字にするときの丸めに使う。センサの分解能を超える桁を送らないことで、通信量を減らし、見かけの精度を誇張しない。補助値のフラグは、上位機器が表示の重みを下げる (小さく表示する、既定では記録しない など) ために使う。

### 拡張ステータス (0x0480〜0x048B)

| 番地 | 長さ | 名称 | 型 | 内容 |
|---|---|---|---|---|
| 0x0480 | 4 B | uptime_s | uint32 | 起動からの秒数。減ったら再起動と判断できる |
| 0x0484 | 1 B | node_flags | uint8 | bit0: 準備中 (予熱中、平均化の時間幅が満ちていない)、bit1: 設定の消失 (起動時に不揮発メモリが壊れていて既定値を使った)。ほかのビットは 0 |
| 0x0485 | 1 B | reset_cause | uint8 | 直近の起動の要因 (下表) |
| 0x0486 | 2 B | err_i2c | uint16 | 上位機器との I²C の異常の回数 (一巡する) |
| 0x0488 | 2 B | err_sensor | uint16 | センサとの通信の異常の回数 (一巡する) |
| 0x048A | 2 B | crc | uint16 | 0x0480〜0x0489 の CRC |

- 子機は、上位機器が番地 0x0480 を指定した時点の値を写し取り、続く読み出しでは写し取った値を返さなければならない。

| reset_cause | 意味 |
|---|---|
| 0 | 不明・未対応 |
| 1 | 電源投入 |
| 2 | 電圧低下 |
| 3 | ウォッチドッグ |
| 4 | ソフトウェアによるリセット |
| 5 | 外部リセット (リセット端子) |
| 6 | その他 |

解説: 異常の内訳 (マイコンの I²C の周辺回路の衝突やバスエラーの回数など) はマイコンに固有なので、必要ならユーザー領域に置く。

### コマンド (0x04C0〜0x04C2)

| 番地 | 長さ | 名称 | 型 | 内容 |
|---|---|---|---|---|
| 0x04C0 | 1 B | cmd_key | uint8 | 0xA5 を書くと解錠する。STOP で元に戻す |
| 0x04C1 | 1 B | cmd | uint8 | コマンドの番号 (下表) |
| 0x04C2 | 1 B | cmd_arg | uint8 | 引数 |

| cmd | 内容 | cmd_arg |
|---|---|---|
| 0x01 | ソフトウェアによるリセット | 無視する |
| 0x02 | 識別: LED などを点滅させる | 点滅の秒数 (0 で止める) |

- 上位機器は、番地 0x04C0 から鍵 0xA5・コマンド・引数の 3 B を、1 回の通信で書かなければならない。
- 子機は、STOP を受けたときに鍵が 0xA5 であれば、コマンドを実行しなければならない。
- コマンドの結果を返すレジスタは持たない。

## ユーザー領域と補正係数

### ユーザー領域の規則

- この仕様は、0x1000〜0xFFFF に何も定義しない。今後も定義しない。
- 中身・形式・読み書きの規則・不揮発メモリへの保存の仕方・CRC の有無は、作り手が決めてよい。
- 上位機器のうち、計測を担うもの (PoEM では PoEM Pod) は、この領域を読み書きしてはならない。設定や校正の道具は、model_id で機種を確かめたうえで、機種ごとに定めた形で読み書きしてよい。
- 番地で始まらない独自の通信が必要な場合は、0x1000 以上の番地をコマンドの番号として扱い、後ろのバイト列を自由な形にしてよい。
- それでも足りない場合は、子機に 2 つ目の I²C アドレスを持たせ、OSL と無関係な通信に使ってもよい。

### 補正の扱い

- 子機が値を補正する場合は、補正した後の値を POLL で公開しなければならない。上位機器は、POLL の値をそのまま使い、補正し直してはならない。
- 補正の方法と係数の置き場所は、ユーザー領域に作り手が定める。

解説: 補正を子機の中で行うので、どの上位機器で読んでも同じ値になる。校正の結果は、子機を別の場所に移しても子機についていく。PoEM の子機の補正の方法は、2.8 節に例として示す。

### 不揮発メモリの内容と工場リセット

- 子機は、I²C アドレス・名前・ユーザー領域の設定を、不揮発メモリに保存しなければならない。
- 起動時に不揮発メモリの内容が壊れていた場合 (CRC の不一致など) は、既定値を使い、拡張ステータスの node_flags の bit1 (設定の消失) を立てなければならない。
- 工場リセットでは、I²C アドレスを工場出荷時の値に、名前を空に、ユーザー領域を既定値に戻す。

未決: 校正の履歴 (日付と係数の世代) をユーザー領域に持つ方法、工場リセットで履歴を残すかどうか、ファームウェアの更新でユーザー領域の形が変わったときの移行の方法は未決である (付録 F)。現在の PoEM の子機は、ユーザー領域の大きさが変わると不揮発メモリの内容を壊れたものとみなし、アドレス・名前・係数を既定値に戻す。

## CRC・状態コード・単位コード

### CRC

| 項目 | 規定 |
|---|---|
| 方式 | CRC-16/CCITT-FALSE |
| 多項式 | 0x1021 |
| 初期値 | 0xFFFF |
| 入力・出力の反転 | なし |
| 最終の XOR | なし |
| 検査値 | ASCII の "123456789" の CRC は 0x29B1 |
| 格納 | リトルエンディアン (下位バイトが先) |

計算の例を示す (C 言語)。

```
uint16_t crc16(const uint8_t *p, uint16_t n)
{
    uint16_t crc = 0xFFFF;
    while (n--) {
        crc ^= (uint16_t)(*p++) << 8;
        for (uint8_t i = 0; i < 8; i++)
            crc = (crc & 0x8000) ? (uint16_t)((crc << 1) ^ 0x1021) : (uint16_t)(crc << 1);
    }
    return crc;
}
```

### 状態コード

POLL の status には、BACnet の Reliability の値をそのまま使う。

| 値 | BACnet での名前 | 付ける者 | 意味 |
|---|---|---|---|
| 0 | NO_FAULT_DETECTED | 子機 | 正常 |
| 1 | NO_SENSOR | 子機 | センサが応答しない |
| 2 | OVER_RANGE | 子機 | 測定範囲の上限を超えた |
| 3 | UNDER_RANGE | 子機 | 測定範囲の下限を下回った |
| 7 | UNRELIABLE_OTHER | 子機 | そのほかの異常 |
| 12 | COMMUNICATION_FAILURE | 上位機器 | 子機を読めない。子機は付けてはならない |
| 64 | (独自) 準備中 | 子機 | 予熱中、平均化の時間幅が満ちていない |

- 最小限の実装では、0 (正常) と 7 (異常) だけを使ってもよい。
- 状態が 0 でないチャネルの値は、上位機器が使ってはならない。

解説: BACnet の値をそのまま使うので、上位機器は状態を変換せずに BACnet の Reliability に書ける。64 は BACnet の規格の外 (独自の値の範囲) にある。

### 単位コード

チャネル記述の unit には、BACnet Engineering Units の値をそのまま使う。PoEM の子機で使う主な値を示す。全体の一覧は付録 B に示す。

| 値 | 単位 |
|---|---|
| 5 | V |
| 29 | %RH |
| 53 | Pa |
| 62 | °C |
| 74 | m/s |
| 95 | 単位なし |

## 子機の振る舞い

### 起動と準備中

- 子機は、起動してから値が有効になるまでの間、すべてのチャネルの状態を 64 (準備中) にしなければならない。
- 準備中の時間は、拡張識別の warmup_ms に示すことを推奨する。
- 平均化をする子機は、平均化の時間幅が満ちるまでを準備中とすることを推奨する。

### センサの異常

- センサが応答しない間は、そのチャネルの状態を 1 にし、sample_seq を増やしてはならない。
- 子機は、センサとの通信の異常を拡張ステータスの err_sensor に数えることを推奨する。
- センサが応答しない状態が続く場合は、センサを初期化し直すことを推奨する。

### 不揮発メモリへの保存の時機

- 名前・アドレス・ユーザー領域の書き込みは、STOP を受けた後、I²C の割り込みの外で保存することを推奨する。保存の間も I²C の応答を止めてはならない。

### 工場リセットの操作

工場リセットの操作方法 (リセットスイッチの長押しなど) は、機種ごとに定める (2.8 節)。リセットスイッチを持たない機種は、上位機器からの書き込み (アドレスと名前とユーザー領域の書き換え) で同じ状態にできる。

### 補正

PoEM の子機は、センサの値を次の式で補正してから公開する。

補正値 = a × 生の値 + b

係数 a、b はチャネルごとにユーザー領域に持ち、既定値は a = 1、b = 0 (補正なし) である。係数が書き換えられると、子機は不揮発メモリに保存し、以後の値に反映する。ユーザー領域の具体的な配置は、機種ごとの内部の定義であり、付録 H に参考として示す。

## 上位機器の手順

この節は、子機を読み書きする上位機器が守る手順を定める。PoEM の上位機器 (PoEM Pod、PoEM Link) に固有の手順は、第 3 章と第 6 章に定める。

### 走査 (子機の発見)

上位機器は、正体の分からない機器に書き込んではならない。子機の発見と正体の確認は、番地を送らない読み出しだけで行わなければならない。

| 段階 | 手順 | 判定 |
|---|---|---|
| 1. 発見と正体の確認 | 0x08〜0x77 の各アドレスから、番地を送らずに 32 B 読む (0x0000 の識別区画が返る) | NACK なら機器なし。magic が "OSL" でない、CRC が合わない、channel_count が 1〜16 でない、spec_version を知らない場合は、OSL の子機ではない |
| 2. 名前 | 0x0040 から 66 B 読み、CRC を確かめる | 合わなければ読み直す |
| 3. チャネル記述 | 0x0100 から 16×N+2 B 読み、CRC を確かめる | 同上 |
| 4. 拡張識別 | 0x0400 から 10 B 読む | CRC を含めてすべて 0 なら任意機能なし。CRC が合わなければ読み直す |
| 5. 拡張チャネル属性 | capability の bit0 が立っていれば、0x0420 から 4×N+2 B 読み、CRC を確かめる | 合わなければ読み直す |

- 段階 1 で OSL の子機でないと判断したアドレスには、以後、書き込んではならない。
- 段階 2 以降の番地を指定した読み出し (番地の書き込みを伴う) は、段階 1 で OSL の子機と確かめた相手にだけ行わなければならない。
- 読み直しは 3 回までとすることを推奨する。

解説: 段階 1 で読み出しに失敗することが、まれにある (読み出し位置の規則により、直前の通信の状態で位置が 0x0000 でないことがある)。この場合は OSL の子機ではないと判断し、次の全体の走査で改めて確かめる。

### 計測値の読み出し

- 上位機器は、update_period_ms を目安に、0x0300 から POLL の長さだけ読み、CRC を確かめる。
- CRC が合わない場合は読み直す。続けて読めない場合は、すべてのチャネルを状態 12 (通信失敗) として扱う。
- sample_seq が前回から変わっていれば、新しい値として取り込む。

### 書き込み

| 操作 | 手順 | 確認 |
|---|---|---|
| 名前の変更 | 0x0040 に 64 B を 1 回の通信で書く | 0x0040 から 66 B 読み、内容と CRC を確かめる |
| アドレスの変更 | 0x0020 に 0xA5 と新しいアドレスを書く | 新しいアドレスで識別を読み、device_id が同じことを確かめる |
| 識別の点滅 | 0x04C0 に 0xA5、0x02、秒数を書く | (なし) |
| リセット | 0x04C0 に 0xA5、0x01、0 を書く | 拡張ステータスの uptime_s の巻き戻りで確かめてもよい |

### 交換と再起動の検知

- 上位機器は、子機を読めなくなった後に同じアドレスで再び読めた場合、識別区画を読み直し、device_id・model_id・チャネル記述が変わっていないことを確かめなければならない。変わっていれば、別の子機として扱わなければならない。
- 上位機器は、拡張ステータスの uptime_s が減ったら子機の再起動とみなし、識別区画を読み直すことを推奨する。

解説: 子機を抜いて別の子機を同じアドレスに挿すと、上位機器はそのまま読み続けてしまい、前の子機の名前・単位・校正の記録で新しい子機の値を扱うおそれがある。読めない期間の後と再起動の後に識別区画を確かめることで、この取り違えを防ぐ。
