# 第3部 Pod (親機) {.unnumbered}

> 元資料: firmware/poem_pod.X (main.c、node_manager.c、i2c_master.c)、メモリの「親機電源構成」。

# ハードウェアの概要

> 執筆予定: マイコン (AVR128DB32)、Ethernet (W5500)、PoE 受電 (Si3404、3.3 V)、I²C の系統 (コネクタ 2 つは並列で 1 系統)、プルアップ、LED とボタン。

# 子機の管理

## 全走査

> 執筆予定: 起動時・再接続時・SCAN ボタンで、ノードと記録を消して 0x08〜0x77 を調べる。1 アドレス分の手順 (番地なしで 32 バイト読む → "OSL" と CRC → チャネル記述・拡張識別・拡張チャネル属性)。書き込みは OSL と確認した後だけ。

## 増分走査

> 執筆予定: 10 秒ごとに、未登録で「OSL 以外」でもないアドレスだけ調べる。

## 交換の検知

> 執筆予定 (新規の規定): comm_ok が false のノードは、POLL の代わりに再プローブする。uptime_s の巻き戻りでも再プローブする。UID か構成が変わったときだけ config を送る。OSL 以外の機器だった場合は POLL をやめ、書き込みをしない。
>
> 元資料: OSL v2 通信の整理 (交換に気づくための案)。

## OSL 以外の機器の扱い

> 執筆予定: 記録して以後は調べない。番地の書き込みをしない。

# 計測の周期と POLL

> 執筆予定: 周期 (現状 1 秒固定。update_period_ms の扱い)、再試行の回数、失敗時に状態 12 を送ること、値が有限でないときの状態 7。仕様と実装の差を解消する方針。

# 設定と Web 画面

> 執筆予定: ネットワーク設定、Pod 名、MQTT の送り先、子機の名前とアドレスの変更、工場リセット。

# 診断

> 執筆予定: I²C の異常回数 (pod/diag)、LED の表示、ウォッチドッグ。
