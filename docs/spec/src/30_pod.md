# PoEM Pod (親機)

この章は、PoEM Pod の機能と振る舞いを定める。PoEM Pod は、OSL の上位機器として子機を読み (第 2 章)、計測値を MQTT で PoEM Server に送る (第 4 章)。

## ハードウェアの概要

| 項目 | 内容 |
|---|---|
| マイコン | AVR128DB32 |
| Ethernet | W5500 (TCP/IP を内蔵した Ethernet コントローラ) |
| 電源 | PoE で受電する。PoE の受電回路 (Si3404) で 3.3 V を作る |
| I²C | 1 系統。Qwiic のコネクタを 2 つ持ち、並列につながる。プルアップ抵抗を持つ |
| ボタン | Reset スイッチ (起動時の設定のモードへの切り替え、工場リセット)、SCAN ボタン (全体の走査) |
| 表示 | LED (緑、赤) |

- 1 台の PoEM Pod は、最大 64 台の子機を扱う。
- 子機への電源 (3.3 V) は、Qwiic の配線で PoEM Pod から供給する。

## 動作のモード

PoEM Pod には、計測のモードと設定のモードがある。

| モード | 入り方 | 内容 |
|---|---|---|
| 計測のモード | 通常の起動 | MQTT ブローカー (PoEM Server) に接続し、子機を読んで計測値を送る |
| 設定のモード | Reset スイッチを押したまま起動する | Web の画面でネットワークや子機の設定を行う。MQTT の通信は行わない |

解説: 設定のモードで MQTT の通信を止めるのは、Ethernet コントローラの通信の窓口 (ソケット) を Web と MQTT で取り合うと、通信が混線するためである。

## 子機の管理

PoEM Pod は、子機ごとにノード (管理用の記録) を持つ。ノードには、I²C アドレス、チャネル数、チャネルの値の型と有効桁数、拡張ステータスの有無、直近に読めたかどうか (通信の状態) を記録する。子機の UID と名前はノードに持たず、必要なときに子機から読む。

解説: 名前をノードに持たないのは、メモリを節約するためである (64 台 × 64 B = 4 KB)。

### 全体の走査

PoEM Pod は、次の時機に全体の走査を行わなければならない。

- MQTT ブローカーへの接続が成立したとき (起動後の初回、切断後の再接続)
- SCAN ボタンが押されたとき

全体の走査では、すべてのノードと「OSL の子機ではないアドレス」の記録を消し、0x08〜0x77 のすべてのアドレスを 2.9.1 項の手順で調べる。走査の前に PoEM Pod の情報 (pod/info) を送り、走査の後に、見つかったすべての子機の config (第 4 章) を送らなければならない。

解説: 接続のたびに全体の走査と config の送信を行うのは、PoEM Server が再起動して子機の情報を失っていても、自動で登録を回復するためである。

### 増分の走査

PoEM Pod は、10 秒ごとに増分の走査を行わなければならない。増分の走査では、ノードが無く、OSL の子機ではないと記録されていないアドレスだけを調べ、新しく見つかった子機の config を送る。

### 交換と再起動の検知

PoEM Pod は、2.9.4 項に従い、子機の交換と再起動を検知しなければならない。

- 通信の状態が「読めない」になったノードについては、POLL の代わりに、毎秒、番地を送らない読み出しで識別区画を読み直す (再プローブ)。
- 識別区画が読め、UID・model_id・チャネル記述が以前と同じなら、通信の状態を「読める」に戻し、POLL を再開する。
- UID・model_id・チャネル記述のいずれかが変わっていれば、ノードを登録し直し、config を送ってから data を送る。
- 応答はあるが OSL の子機ではない場合は、そのアドレスを「OSL の子機ではない」と記録し、ノードの POLL をやめ、以後、書き込みをしない。
- 拡張ステータスの uptime_s が前回より減った場合も、同じ手順で確かめる。
- config は、UID か構成が変わったときだけ送る。読み損じ (ノイズによる CRC の不一致など) から回復しただけのときは送らない。

解説: 子機を抜くと POLL が読めなくなる。再プローブにより、同じアドレスに別の子機を挿したとき、前の子機の名前・単位・校正の記録で新しい子機の値を扱う取り違えを防ぐ。再プローブは書き込みを伴わないので、同じアドレスに OSL 以外の機器が挿されても、その機器に書き込まない。抜き差しが POLL の周期より短く、読めない期間が生じなかった場合は、uptime_s の巻き戻りで検知する。

### OSL の子機ではない機器

- PoEM Pod は、OSL の子機ではないと判断したアドレスを記録し、以後、そのアドレスに書き込んではならない。
- 記録は、次の全体の走査まで保持する。

## 計測値の読み出し

- PoEM Pod は、1 秒ごとに、すべてのノードの POLL を読み、ノードごとに data を 1 つ送らなければならない。
- POLL の CRC が合わない場合は、読み直さなければならない (合計 3 回まで)。
- 3 回とも読めない場合は、すべてのチャネルを状態 12 (通信失敗) とする data を送り、ノードの通信の状態を「読めない」にしなければならない。ノードは消さない。
- float32 の値が有限でない (NaN、無限大) 場合は、そのチャネルの状態を 7 (異常) にしなければならない。
- 値は、チャネルの有効桁数 (拡張チャネル属性) で丸めて送る。有効桁数が無い場合は 6 桁とする。

解説: 子機の update_period_ms は 1 秒より短いことが多いが、BMS での監視と記録には 1 秒ごとで足りる。このため、読み出しの周期は全機種で 1 秒とした。新しい値かどうかの判断 (sample_seq の比較) は PoEM Pod では行わず、sample_seq を data に入れて送る。

## 拡張ステータスの確認

- PoEM Pod は、拡張ステータスを持つ子機について、10 秒ごとに拡張ステータスを読まなければならない。
- 前回から変わっていれば、node/diag (第 4 章) を送る。

## 設定

### 設定の項目

設定のモードの Web の画面で、次の項目を設定する。設定は不揮発メモリに保存する。

| 項目 | 内容 |
|---|---|
| IP アドレス、サブネットマスク、ゲートウェイ、DNS | PoEM Pod のネットワークの設定 |
| ブローカーの IP アドレス | MQTT の接続先 (PoEM Server) |
| PoEM Pod の名前 | 利用者が付ける呼び名 (20 B まで)。pod/info で送る |
| 子機の I²C アドレス | つながっている子機ごとに変更できる |
| 子機の名前 | つながっている子機ごとに変更できる (UTF-8、63 B まで) |

- PoEM Pod の名前を JSON に入れるとき、JSON を壊す文字 (二重引用符、逆斜線、制御文字) は別の文字に置き換えなければならない。途中で切れた多バイト文字は取り除かなければならない。

### 工場リセット

設定のモードで Reset スイッチを 5 秒押し続けると、PoEM Pod の設定を工場出荷時の値に戻す。

## 表示と診断

### LED

| 表示 | 意味 |
|---|---|
| 緑が 1 回点滅 | 1 秒ごとの計測値の送信が終わった |
| 緑が 2 回点滅 | 増分の走査で子機が増えた。全体の走査が終わった |
| 赤が 2 回点滅 (繰り返し) | 起動後、MQTT ブローカーに接続できない |
| 赤が 3 回点滅 (繰り返し) | MQTT ブローカーとの接続が切れ、再接続を試みている |
| 赤が点灯 | 設定のモード |

### 診断

PoEM Pod は、1 秒ごとに I²C の診断の情報 (pod/diag、第 4 章) を送る。I²C のバスが固着した場合は、復帰の手順 (SCL を 9 回動かして STOP を作る) を実行し、その回数を記録する。
