# PoEM Link と補助ソフト

この章は、PoEM Link と、PoEM Link 用アプリ、PC 用の道具を定める。PoEM Link は、OSL の上位機器として子機を直接読み書きする (第 2 章)。PoEM の常設の計測 (PoEM Pod から BMS まで) を補助するもので、設置前の準備、動作確認、短期の計測、校正に使う。

## PoEM Link のハードウェア

| 項目 | 内容 |
|---|---|
| マイコン | AVR32DU20 (USB を内蔵。水晶を使わず、USB の信号で時計を補正する) |
| USB | USB Type-C。USB-MIDI 1.0 のクラスに準拠し、専用のドライバを要しない |
| I²C | Qwiic のコネクタ 1 つ。約 5 kΩ のプルアップ抵抗を持つ |
| 電源 | USB のバス電源 (5 V) から 3.3 V を作り、マイコンと子機に供給する |
| 表示 | LED 1 つ |

- PoEM Link は、iPhone・Android・Windows・Mac に接続できる。Lightning 端子の iPhone には、Lightning - USB 3 カメラアダプタを介してつなぐ。
- 子機への電源は、接続先の機器の USB の給電能力の範囲で供給する。給電能力の大きい子機 (風速センサなど) を複数つなぐ場合は、接続先の機器の給電能力を確かめなければならない。

解説: USB-MIDI を使うのは、iPhone を含むすべての OS で、ドライバや機器の認証なしに使えるためである。

## USB-MIDI の通信仕様

### 方針

PoEM Link のファームウェアは、I²C の転送だけを行い、OSL の内容を解釈しない。OSL の解釈 (走査、識別、名前、チャネル、POLL、CRC) は、すべて上位のソフトウェア (PoEM Link 用アプリ、PC の道具) が行う。このため、PoEM Link は OSL 以外の Qwiic の機器にも使える。

### USB の識別

| 項目 | 内容 |
|---|---|
| クラス | USB-MIDI 1.0 (入力 1 系統、出力 1 系統) |
| 速度 | Full Speed (12 Mbps) |
| 製品の文字列 | PoEM Link |
| MIDI のポートの名前 | PoEM Link {マイコンの固有番号から作る 16 進 8 桁} |
| 消費電流の申告 | 100 mA |

### メッセージの形

要求と応答は、MIDI の SysEx で送る。

| 欄 | 長さ | 内容 |
|---|---|---|
| F0 | 1 B | SysEx の開始 |
| MFR | 1 B | メーカー ID。開発中は 0x7D (非商用) |
| PRODUCT | 1 B | 製品コード。0x02 = PoEM Link |
| SEQ | 1 B | 通し番号 (0x00〜0x7F)。要求の側が付け、応答で同じ値を返す |
| CMD | 1 B | 要求は 0x01〜0x3F。応答は同じ番号に 0x40 を足した値 |
| ペイロード | 可変 | 8-to-7 の符号化をしたバイト列 |
| F7 | 1 B | SysEx の終了 |

- 応答のペイロードの先頭の 1 B は、必ず結果コード (6.2.7 項) としなければならない。
- 多バイトの数値はリトルエンディアンとする。
- MFR または PRODUCT が一致しないメッセージは、応答せずに捨てなければならない。

### 8-to-7 の符号化

SysEx の中では各バイトの最上位ビットを使えないので、元のバイト列を 7 B ずつに区切り、各組の前に「最上位ビットをまとめたバイト」を置く。

- まとめたバイトの bit i は、組の i 番目のバイトの bit7 とする。各バイトは下位 7 ビットだけを送る。
- 最後の組が 7 B に満たない場合は、その分だけ短くする。
- 元の n B は、符号化すると n + ⌈n/7⌉ B になる。

例: 元の 10 20 00 は、00 10 20 00 になる。元の FF 01 は、01 7F 01 になる。

### やり取りの約束

- 要求は 1 つずつ送る。応答を受けてから次の要求を送らなければならない。
- 要求の側は、1 つの要求について 500 ms を目安に応答を待ち、来なければ同じ SEQ で 1 回送り直す。
- PoEM Link は、要求への応答以外のメッセージを自ら送らない。
- SysEx 自体には CRC を付けない (USB の転送に誤りの検出と再送がある)。I²C の内容の化けは、OSL の区画の CRC で検出する。

MIDI の標準の機器の問い合わせ (Device Inquiry、F0 7E 7F 06 01 F7) にも応答する。応答の family は 0x0002 (PoEM Link)、model は 0x0001 とし、ファームウェアの版を含める。

### コマンド

| CMD | 名前 | 要求 | 応答 (結果コードの後) |
|---|---|---|---|
| 0x01 | GET_INFO | なし | プロトコルの版、ファームウェアの版、1 回の転送の上限 (256)、BATCH の応答の上限 (512)、I²C の速度、タイムアウト、機能のビット、固有番号 (16 B) |
| 0x02 | SET_CONFIG | I²C の速度 [kHz] (100 または 400)、タイムアウト [ms] (10〜1000)。0 は変えない | 設定後の速度とタイムアウト |
| 0x10 | PROBE | アドレス | なし (結果コードで応答の有無を示す) |
| 0x11 | SCAN | 最初と最後のアドレス | 応答したアドレスのビット表 (16 B) |
| 0x20 | READ | アドレス、長さ | 読めた長さ、データ |
| 0x21 | WRITE | アドレス、データ | ACK されたバイト数 |
| 0x22 | WRITE_READ | アドレス、書く長さ、書くデータ、読む長さ | 読めた長さ、データ |
| 0x30 | BATCH | 中止の指定、操作の数 (1〜64)、操作 (READ・WRITE・WRITE_READ) | 実行した操作の数、操作ごとの結果 |
| 0x31 | BUS_STATUS | なし | SDA と SCL の電位、バスの状態、異常の回数 |
| 0x32 | BUS_RECOVER | なし | 復帰後の SDA と SCL の電位 |
| 0x38 | LED | モード (0: 自動、1: 識別の点滅)、秒数 | なし |
| 0x3E | REBOOT | なし | なし (応答の後に再起動する) |

- PROBE と SCAN は、アドレスに読み出しの 1 B を送るだけで、書き込みを行ってはならない (2.9.1 項の安全な走査のため)。
- READ は、番地を送らずに読む (OSL の識別区画の確認に使う)。
- WRITE_READ は、書いた後に STOP を挟まず、Repeated START で読む。
- BATCH は、毎周期の POLL などで、USB の往復の回数を減らすために使う。応答のデータの合計が 512 B を超える要求は、BAD_LENGTH で拒否しなければならない。

### 結果コード

| 値 | 名前 | 意味 |
|---|---|---|
| 0x00 | OK | 成功 |
| 0x01 | NACK_ADDR | アドレスに応答が無い (機器が無い) |
| 0x02 | NACK_DATA | 書き込みの途中で NACK された |
| 0x03 | TIMEOUT | 転送が時間内に終わらなかった |
| 0x04 | BUS_BUSY | 開始の前にバスが使用中だった |
| 0x05 | ARB_LOST | 調停に負けた (別のマスタと衝突した) |
| 0x06 | BUS_STUCK | SDA または SCL が Low のままで、復帰できなかった |
| 0x07 | BUS_ERROR | 不正な START・STOP を検出した |
| 0x10 | BAD_LENGTH | 長さが範囲外 |
| 0x11 | BAD_PARAM | 値が範囲外 |
| 0x12 | UNKNOWN_CMD | 未定義のコマンド |
| 0x13 | BAD_ENCODING | 8-to-7 の符号化が不正 |

### I²C の動作

- 既定の速度は 100 kHz、1 回の転送のタイムアウトは 100 ms とする。
- 転送の開始の前にバスが空いているかを確かめ、5 ms 待っても空かなければ BUS_BUSY を返さなければならない。動作中の PoEM Pod のバスに誤ってつながれた場合に、通信を割り込ませないためである。
- タイムアウトやバスの固着を検出した場合は、1 回だけ復帰を試みる (SCL を 9 回動かし、STOP を作り、I²C の周辺回路を初期化し直す)。

### LED

| 状態 | 表示 |
|---|---|
| USB に未接続 (構成前) | 1 秒の周期で点滅 |
| USB に接続済み | 点灯 |
| I²C の転送 | 転送ごとに短く消える |
| バスの固着が続いている | 速く点滅 |
| 識別 (LED のコマンド) | 2 Hz で点滅 |

### メーカー ID

開発中は、MIDI の非商用のメーカー ID 0x7D を使う。一般に配布する前に、正式なメーカー ID を取得しなければならない (付録 F)。

## PoEM Link 用アプリ

### 位置づけ

PoEM Link 用アプリは、PoEM の補助のソフトウェアである。iPhone・Android・Windows で動く。画面はスマートフォンでの使用を優先して作る。

### 機能

| 機能 | 内容 |
|---|---|
| 子機の自動の検出 | PoEM Link を接続すると、2.9.1 項の手順で子機を探す。3 秒ごとに走査し直し、子機の抜き差しとアドレスの変更に追従する |
| 計測値の表示 | 子機が名乗るチャネルの名前・単位・有効桁数・状態に従って表示する。機種ごとの作り込みをしない |
| 記録と書き出し | 計測値を一定の間隔 (1〜60 秒) で記録し、CSV で書き出す |
| 子機の設定 | 名前とアドレスの変更、識別の点滅 |
| 診断 | PoEM Link のファームウェアの版・固有番号、I²C のバスの状態、バスの復帰 |
| 模擬モード | PoEM Link と子機を模擬し、機器なしで画面と記録を試す |

- PoEM Link 用アプリは、OSL の子機ではない機器に書き込んではならない。
- PoEM Link 用アプリは、ユーザー領域を読み書きしない。

### 記録の形式

CSV は、1 行目を見出しとし、2 行目以降に時刻ごとの値を書く。

| 列 | 内容 |
|---|---|
| Date、Time | 記録した日付と時刻 (PoEM Link 用アプリを動かす機器の時計) |
| {子機の名前}\_{チャネル名}[{単位}] | チャネルの値。表示の桁で丸めず、子機が送った値をそのまま書く |
| {子機の名前}\_{チャネル名}[{単位}] status | チャネルの状態 (2.6.2 項の値) |

- 名前の無い子機は、子機の名前の代わりに I²C アドレスを使う。
- 記録の途中で子機が増えたら、列を右に足す。読めなくなった子機の値は空欄とし、状態を 12 とする。

## 校正

子機の校正は、子機のユーザー領域にある補正の係数を書き換えて行う (PoEM の子機の例は 2.8.3 項)。

- 校正では、係数を書き換えた後に読み返し、書いた値と一致することを確かめなければならない。
- 校正に使う道具 (PoEM Link 用アプリに機能を加えるか、PC の道具で行うか)、校正の履歴 (日付と係数の世代) を子機に残す方法は未決である (付録 F)。

## PC 用の道具

PC の Python の道具 (software/tools/python) で、子機を直接読み書きできる。USB と I²C の変換器 (CP2112、MCP2221) を使う。

| 道具 | 内容 |
|---|---|
| osl.py | OSL の解釈の部品 (走査、識別、名前、チャネル、POLL、CRC、ユーザー領域) |
| osl_reader.py | 子機を探し、計測値を表示・記録する |
| osl_plot.py | 計測値をグラフで表示する |
| osl_set.py | 名前・アドレス・ユーザー領域を書き換える |
| osl_v2_test.py | 子機の OSL の実装を試験する |
| dump_memory.py | 子機の番地の内容を表示する |
| i2c_scan.py | I²C のバスの機器を一覧する |
