# 総論

## 目的と適用範囲

### OSL と PoEM

この文書は、OSL と PoEM の 2 つを定める。

OSL (OSL 共通レジスタ) は、I²C でつながるセンサ機器のための汎用の共通レジスタの仕様である。センサ機器 (子機) が自分の計測内容 (チャネルの名前・単位・値の型・状態) を名乗り、上位の機器は機種を知らなくても計測値を読めるようにする。OSL は特定の製品やシステムに依存しない。第 2 章で定める。

PoEM は、OSL を使った計測システムの実装の一つである。建物の室内環境と設備の状態を多数の小さな計測器で測り、建物の既存の BMS に取り込む。第 3 章以降で定める。

### PoEM の目的

PoEM の目的は次のとおりである。

- 温度・湿度・風速・差圧・気圧などを、部屋や機器ごとに多点で計測する。
- 計測器 (子機) を安価で小さくし、設置と交換を容易にする。
- 計測値を BACnet で公開し、特定の BMS の製品に依存せずに取り込めるようにする。
- 計測値の信頼性 (センサの異常、通信の途絶、起動直後の準備中) を、値とともに BMS へ伝える。

### 適用範囲

この仕様は、特定の現場ではなく、建築一般の現場で使えることを前提とする。BMS の製品や現場ごとの命名の慣習に依存する事項は、設定や名前の側で吸収し、仕様の本体には持ち込まない。

次の事項は、この仕様の対象外とする。

- 設備の制御 (BACnet での書き込みによる操作)
- 警報の発報と通知 (BMS の側で行う)
- 取引や課金に使う計量
- 計測値の長期の保存 (BMS や別の記録システムで行う)

## システムの構成

### 構成要素

| 構成要素 | 役割 |
|---|---|
| 子機 | センサの値を読み、補正し、OSL (第 2 章) で提供する |
| PoEM Pod | 子機を I²C で見つけて読み、計測値を MQTT で送る。1 台の PoEM Pod は 1 系統の I²C に最大 64 台の子機を持つ |
| PoEM Server | MQTT ブローカーとして PoEM Pod からの電文を受け、BACnet の 1 台の Device として BMS に公開する |
| BMS | BACnet/IP で PoEM Server を読み、監視・記録・警報を行う。PoEM の外にある |
| PoEM Link | スマートフォンや PC に USB でつなぎ、子機を直接読み書きする |
| PoEM Link 用アプリ | PoEM Link を使い、設置前の準備、動作確認、短期の計測と記録を行う。この仕様書に定めた機能だけを使う |
| PoEM Tap | Qwiic の配線を分岐・延長し、1 系統の I²C に複数の子機をつなぐ。プルアップ抵抗を持ち、入切できる |

### データの流れ

計測値は、子機から I²C (Qwiic の配線) で PoEM Pod へ、PoEM Pod から MQTT (Ethernet、PoE で給電) で PoEM Server へ、PoEM Server から BACnet/IP で BMS へ流れる。

補助の経路として、子機から I²C で PoEM Link へ、PoEM Link から USB-MIDI でスマートフォン・PC の PoEM Link 用アプリへ流れる経路がある。

| 区間 | 通信 | 定める章 |
|---|---|---|
| 子機と上位機器 (PoEM Pod、PoEM Link) | I²C、OSL | 第 2 章 |
| PoEM Pod と PoEM Server | MQTT | 第 3 章、第 4 章 |
| PoEM Server と BMS | BACnet/IP | 第 5 章 |
| PoEM Link とスマートフォン・PC | USB-MIDI | 第 6 章 |

- 子機と PoEM Pod は時計を持たない。計測値の時刻は、PoEM Server が電文を受け取った時刻とする。
- PoEM Pod は子機の値を解釈しない。子機が名乗るチャネルの定義 (名前・単位・型) に従って、値をそのまま送る。
- PoEM Server は MQTT ブローカーを兼ねるので、ほかの MQTT クライアントも PoEM Pod の電文を購読できる。

### 識別子の種類

PoEM で使う識別子には、利用者が設定・管理できるものと、機器に固有で利用者が変えられないものがある。

利用者が設定・管理できる識別子は、建物の中の場所 (どの PoEM Server の、どの PoEM Pod の、どの位置の子機か) に対応させて決める。機器を交換しても同じ値を引き継げるので、BMS の点の識別に使う。機器に固有の識別子は、機器の個体を区別するために使う。機器を交換すると変わる。

| 対象 | 利用者が設定・管理できる識別子 | 機器に固有の識別子 |
|---|---|---|
| PoEM Server | BACnet の Device 番号 (既定は IP アドレスの末尾) | — |
| PoEM Pod | PoEM Pod の番号 (PoEM Server が振り、設定ファイルで変えられる)、PoEM Pod の名前 | PoEM Pod の ID (MAC アドレス由来、16 進 12 桁) |
| 子機 | I²C アドレス (同じ PoEM Pod の中で一意)、子機の名前、TSC コード | UID (16 B) |
| チャネル | — | チャネル番号 (子機の中で 0 から。機種で決まる) |

チャネル番号は利用者が変えられないが、機種で決まる番号であり、個体によっては変わらない。同じ機種の子機に交換すれば、同じチャネル番号が同じ計測値を指す。

BACnet のオブジェクトの番号は、PoEM Server が詰めて振り、利用者が設定・管理できる識別子 (PoEM Pod の番号、I²C アドレス) とチャネル番号に対応づけて固定する (第 5 章)。このため、子機を同じ機種の別の個体に交換しても、BMS の点の番号は変わらない。

## 設計の原則

PoEM の各部は、次の原則に従って設計しなければならない。各章の規定は、この原則を具体化したものである。

1. 子機が自分の計測内容を名乗る。子機は、チャネルの名前・単位・値の型・有効桁数・状態を自ら提供する。PoEM Pod・PoEM Server・PoEM Link 用アプリは、機種ごとの作り込みをせず、子機が名乗る内容に従って処理する。
2. BMS の点の番号は、場所 (利用者が管理できる識別子) に対応づけて固定する。センサを交換しても変えない。個体は 16 B の UID で区別する。
3. BACnet のオブジェクトの番号は、一般の現場の慣習に合わせて、オブジェクトの種類ごとに 0 から詰めて振る。
4. 正体の分からない機器には書き込まない。OSL の子機であることを読み出しだけで確かめ、確かめられない機器には一切書き込まない。
5. 異常は値とともに伝える。子機の状態は BACnet の Reliability の値で表す。正常でない間、BACnet の値は最後の正常値のまま据え置き、異常であることを Reliability と STATUS_FLAGS で示す。
6. 時刻はサーバで付ける。子機と PoEM Pod は時計を持たない。

解説: 原則 1 により、新しい機種の子機を作っても、上位の機器やソフトウェアを変更せずに使える。原則 3 は、インスタンス番号の振り方が BACnet Device の側の責任であり、一般の現場では種類ごとに 0 から欠番なく振ることに合わせたものである。原則 4 により、I²C のバスに PoEM 以外の機器が混在しても、その機器の設定を壊さない。

## 版

次の版を、それぞれ独立に管理する。

| 対象 | 版の表し方 | 置き場所 |
|---|---|---|
| OSL | 整数 (この文書では 2) | 子機の識別区画の spec_version (2.3.1 項) |
| 子機のファームウェア | major.minor.patch | 子機の識別区画の fw_version (2.3.1 項) |
| PoEM Pod のファームウェア | major.minor.patch | MQTT の pod/info (第 4 章) |
| PoEM Server | major.minor.patch | 起動時の表示 |
| PoEM Link のファームウェア | major.minor.patch | PoEM Link の GET_INFO (第 6 章) |
| この文書 | 版番号と日付 | 表紙と改訂履歴 |

- OSL の版は、既存の区画の意味や配置を変えるときに上げる。区画の追加は、未実装の番地が 0 を返す規則 (2.1.5 項) により既存の上位機器と両立するので、版を上げなくてよい。
- 上位機器は、spec_version が自分の知らない値の子機を、OSL の子機として扱ってはならない。
