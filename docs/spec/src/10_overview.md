# 総論

## 目的と適用範囲

PoEM は、建物の室内環境と設備の状態を多数の小さな計測器で測り、建物の既存の BMS に取り込むための計測システムである。

PoEM の目的は次のとおりである。

- 温度・湿度・風速・差圧・気圧などを、部屋や機器ごとに多点で計測する。
- 計測器 (子機) を安価で小さくし、設置と交換を容易にする。
- 計測値を BACnet で公開し、特定の BMS の製品に依存せずに取り込めるようにする。
- 計測値の信頼性 (センサの異常、通信の途絶、起動直後の準備中) を、値とともに BMS へ伝える。

この仕様は、特定の現場ではなく、建築一般の現場で使えることを前提とする。BMS の製品や現場ごとの命名の慣習に依存する事項は、設定や名前の側で吸収し、仕様の本体には持ち込まない。

次の事項は、この仕様の対象外とする。

- 設備の制御 (BACnet での書き込みによる操作)
- 警報の発報と通知 (BMS の側で行う)
- 取引や課金に使う計量
- 計測値の長期の保存 (BMS や別の記録システムで行う)

## システムの構成

### 構成要素

| 構成要素 | 役割 |
|---|---|
| 子機 | センサの値を読み、補正し、OSL 共通レジスタ (第 2 章) で提供する |
| Pod (親機) | 子機を I²C で見つけて読み、計測値を MQTT で送る。1 台の Pod は 1 系統の I²C に最大 64 台の子機を持つ |
| PoEMServer | MQTT ブローカーとして Pod からの電文を受け、BACnet の 1 台の Device として BMS に公開する |
| BMS | BACnet/IP で PoEMServer を読み、監視・記録・警報を行う。PoEM の外にある |
| PoEM Link | スマートフォンや PC に USB でつなぎ、子機を直接読み書きする。設置前の準備、動作確認、短期の計測、校正に使う |
| PoEM Tap | Qwiic の配線を分岐し、1 系統の I²C に複数の子機をつなぐ |

### データの流れ

計測値は次の経路で流れる。

```
子機 ── I²C (Qwiic) ── Pod ── MQTT (Ethernet, PoE) ── PoEMServer ── BACnet/IP ── BMS
```

補助の経路として、PoEM Link を使う経路がある。

```
子機 ── I²C (Qwiic) ── PoEM Link ── USB-MIDI ── スマートフォン・PC のアプリ
```

- 子機と Pod は時計を持たない。計測値の時刻は、PoEMServer が電文を受け取った時刻とする。
- Pod は子機の値を解釈しない。子機が名乗るチャネルの定義 (名前・単位・型) に従って、値をそのまま送る。
- PoEMServer は MQTT ブローカーを兼ねるので、ほかの MQTT クライアントも Pod の電文を購読できる。

### 識別の階層

PoEM では、識別に使う値を「場所」と「個体」に分ける。場所の識別子は設置の位置で決まり、機器を交換しても変わらない。個体の識別子は機器に固有で、機器を交換すると変わる。

| 対象 | 場所の識別子 | 個体の識別子 | 決める者 |
|---|---|---|---|
| PoEMServer | BACnet の Device 番号 (既定は IP アドレスの末尾) | — | 設定 (第 5 章) |
| Pod | Pod の番号 (PoEMServer が振る) | Pod ID (MAC アドレス由来、16 進 12 桁) | PoEMServer と Pod (第 3 章・第 5 章) |
| 子機 | I²C アドレス (同じ Pod の中で一意) | UID (16 B) | 設置時の設定と子機 (第 2 章) |
| チャネル | チャネル番号 (子機の中で 0 から) | — | 子機 (第 2 章) |

BACnet のオブジェクトの番号は、場所の識別子 (Pod の番号、I²C アドレス、チャネル番号) だけから決める (第 5 章)。

## 設計の原則

PoEM の各部は、次の原則に従って設計しなければならない。各章の規定は、この原則を具体化したものである。

1. 子機が自分の計測内容を名乗る。子機は、チャネルの名前・単位・値の型・有効桁数・状態を自ら提供する。Pod・PoEMServer・アプリは、機種ごとの作り込みをせず、子機が名乗る内容に従って処理する。
2. 番号は場所、ID は個体。BACnet のオブジェクトの番号は Pod と I²C アドレスで決め、センサを交換しても変えない。個体は 16 B の UID で区別する。
3. BMS は番号だけで点を区別する前提で設計する。1 台の BACnet Device の中では、オブジェクトの種類が違っても番号を重ねない。
4. 正体の分からない機器には書き込まない。OSL の子機であることを読み出しだけで確かめ、確かめられない機器には一切書き込まない。
5. 異常は値とともに伝える。子機の状態は BACnet の Reliability の値で表す。正常でない間、BACnet の値は最後の正常値のまま据え置き、異常であることを Reliability と STATUS_FLAGS で示す。
6. 時刻はサーバで付ける。子機と Pod は時計を持たない。

解説: 原則 1 により、新しい機種の子機を作っても、上位の機器やソフトウェアを変更せずに使える。原則 3 は、一般の BMS がオブジェクトの番号を点の ID として扱うことに合わせたものである。原則 4 により、I²C のバスに PoEM 以外の機器が混在しても、その機器の設定を壊さない。

## 版と互換性

### v1 から v2 への移行

PoEM の子機の共通レジスタには v1 と v2 がある。v2 は、v1 の問題 (機種を区別できない、チャネル数が 8 までに限られる、化けたデータを検出できない、名前を持てない など) を解決するために作り直したものであり、v1 との互換性を持たない。

- v1 の子機・Pod・PoEMServer は、v2 に一斉に移行する。v1 と v2 を同じシステムに混在させてはならない。
- 子機の UID (16 B) は、v1 で個体 ID の計算に使っていたマイコンの固有番号と同じ値である。このため、v1 で使っていた 22 ビットの個体 ID は、v2 でも UID から同じ値を計算できる。

### 版の付け方

次の版を、それぞれ独立に管理する。

| 対象 | 版の表し方 | 置き場所 |
|---|---|---|
| OSL 共通レジスタ | 整数 (現在は 2) | 子機の識別区画の spec_version (2.3.1 項) |
| 子機のファームウェア | major.minor.patch | 子機の識別区画の fw_version (2.3.1 項) |
| Pod のファームウェア | major.minor.patch | MQTT の pod/info (第 4 章) |
| PoEMServer | major.minor.patch | 起動時の表示 |
| この文書 | 版番号と日付 | 表紙と改訂履歴 |

- OSL 共通レジスタの版は、既存の区画の意味や配置を変えるときに上げる。区画の追加は、未実装の番地が 0 を返す規則 (2.2 節) により既存の上位機器と両立するので、版を上げなくてよい。
- 上位機器は、spec_version が自分の知らない値の子機を、OSL の子機として扱ってはならない。
