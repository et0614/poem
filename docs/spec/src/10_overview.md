# 第1部 総論 {.unnumbered}

# 目的と適用範囲

> 執筆予定: PoEM の目的 (建築設備の環境計測を、安価な子機と既存の BMS で実現する)。対象とする建物・計測項目・BMS。対象外とするもの (制御、警報の発報、課金計量など)。特定の現場ではなく建築一般を対象とすること。

# システムの構成

## 構成要素

> 執筆予定: 子機、Pod (親機)、PoEMServer、BMS、PoEM Link、PoEM Tap、PC・スマートフォン。それぞれの役割を 1〜2 文で。

## データの流れ

> 執筆予定: 子機 → I²C (Qwiic) → Pod → MQTT → PoEMServer → BACnet/IP → BMS。補助の経路として 子機 → PoEM Link (USB-MIDI) → アプリ・PC。構成図を figures/ に置く。

## 識別の階層

> 執筆予定: サーバ (BACnet Device)、Pod (MAC 由来の Pod ID と、サーバが振る Pod の番号)、子機 (I²C アドレス = 場所、UID = 個体)、チャネル。どの値が何を識別するかの一覧表。

# 設計の原則

> 執筆予定 (規定として書く):
>
> - 子機が自分の計測内容 (チャネルの名前・単位・型・桁数・状態) を名乗る。上位は機種ごとの作り込みをしない。
> - 番号は場所、ID は個体。BACnet の番号は Pod とアドレスで決め、センサを交換しても変えない。個体は 16 バイトの UID で区別する。
> - BMS は番号だけで点を区別する前提で設計する (Device の中で番号を重ねない)。
> - OSL 子機と確認できない機器には書き込まない。
> - 異常は BACnet の Reliability で伝え、異常の間は値を最後の正常値のまま据え置く。
> - 時刻はサーバで付ける。子機と Pod は時計を持たない。

# 版と互換性

> 執筆予定: v1 (旧共通レジスタ) から v2 への移行で互換を取らなかったこと。仕様の版 (spec 版数、ファームウェアの版、MQTT の版、サーバの版) の付け方と、後方互換の扱い。元資料: Drive の OSL共通レジスタ改善案.md。
