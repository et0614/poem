# 子機読み出しツール (OSL v2、MCP2221 / CP2112)

親機 (PoEM Pod) を使わずに、Windows PC から USB-I2C ブリッジで子機を直接読むための Python スクリプト群。
子機単体の動作確認、I2C アドレス・名前の設定、計測値の記録、v2 仕様への適合試験に使う。

対象は **OSL 共通レジスタ v2** の子機 (仕様: `OSL共通レジスタv2_アドレス表.md`)。v1 の子機は読めない
(v1 のツールは git のタグ `v1` に残っている)。

## 構成

| ファイル | 層 | 内容 |
|---|---|---|
| `mcp2221_driver.py` / `cp2112_driver.py` | L3 (I2C) | USB-I2C ブリッジ。番地の形を問わない汎用の I2C 操作 (`probe` / `i2c_read` / `i2c_write` / `i2c_write_read`) を持つ |
| `osl.py` | L4 (OSL v2) | v2 の解釈。走査・識別・名前・チャネル・計測値 (POLL)・拡張区画・CRC・ユーザー領域 |
| `osl_reader.py` | ツール | 子機の情報表示、計測値の連続表示と CSV 記録 |
| `osl_plot.py` | ツール | `osl_reader.py --plot` のグラフ表示 |
| `osl_set.py` | ツール | アドレス・名前・ユーザー領域の値の変更、リセット、識別表示 |
| `osl_v2_test.py` | ツール | v2 仕様への適合試験 |
| `dump_memory.py` | ツール | 任意の番地からの 16 進ダンプ |
| `i2c_scan.py` | ツール | I2C バスの応答アドレスを列挙 (CP2112) |

`osl.py` は I2C の手段を「バス」として受け取るので、PoEM Link (USB-MIDI) 用のバスを足せば、
同じコードでスマホや PoEM Link からも子機を扱える。

## 準備

```
pip install hidapi
pip install matplotlib      # グラフ表示 (--plot) を使うときだけ
```

- MCP2221 / CP2112 はどちらも Windows の標準 HID として認識されるので、ドライバのインストールは要らない。
- 子機の SDA / SCL / GND をブリッジにつなぎ、子機に電源を入れる。I2C のプルアップ抵抗がバス上のどこかに必要。
- ブリッジは自動で選ぶ (MCP2221 → CP2112 の順)。`--bridge mcp2221` / `--bridge cp2112` で固定、
  `--serial XXXX` で複数台から選べる。

## osl_reader.py — 子機の情報を読む

```
python osl_reader.py                            バスを走査し、見つかった子機をすべて表示
python osl_reader.py --addr 0x10                指定アドレスの子機だけ表示
python osl_reader.py --watch 1                  1 秒ごとに計測値を表示し、CSV にも書き出す
python osl_reader.py --watch 1 --csv log.csv    CSV のファイル名を指定する (子機ごとに log_0xNN.csv)
python osl_reader.py --plot                     計測値をグラフでリアルタイム表示する (1 秒ごと)
python osl_reader.py --plot --span 3600         グラフの横軸を直近 1 時間にする (既定 600 秒)
```

走査は v2 の手順 (仕様 §7.1) に従う。番地を送らずに読み出して `"OSL"` と CRC を確かめるので、
同じバスにつながった他の I2C 機器に書き込むことはない。

### 表示例

```
[0x10] 差圧センサ (SDP810-125Pa)
  Vendor    : PoEM  model 0x0302  fw 2.0.0  spec v2
  Device ID : 0102030405060708090A0B0C0D0E0F10
  Name      : "3F 会議室 天井"
  更新周期  : 125 ms
  ch0       : DP [Pa]  (有効桁 4)
  ch1       : Temp [°C]  (有効桁 4, 補助値)
  Values    : DP 1.23 Pa, Temp 24.50 °C   (sample_seq 812)
  拡張      : capability 0x0007  hw_rev 0  平均 1000 ms  予熱 1000 ms
  状態      : 稼働 101 s  起動要因 電源投入  I2C異常 0  センサ異常 0
  ユーザー領域: dp_a=1, dp_b=0Pa, temp_a=1, temp_b=0°C
```

| 項目 | 意味 |
|---|---|
| model | 機種 (仕様 §6.1)。機種名とユーザー領域の項目は `osl.py` の `MODELS` で引く |
| Device ID | 個体 ID (16 バイト)。AVR ではマイコン固有のシリアル番号 |
| Name | 利用者が付ける呼び名 (UTF-8、63 バイトまで) |
| ch | チャネル名と単位 (チャネル記述)。有効桁・補助値は拡張チャネル属性 |
| Values | 計測値。正常でないチャネルには状態 (準備中・センサ応答なし など) を添える |
| sample_seq | 子機が新しい値を公開するたびに +1 する番号 |
| 状態 | 拡張ステータス。稼働時間・直近の起動要因・異常の回数 |
| ユーザー領域 | 機種固有の設定 (補正係数など)。0x1000 以降 |

### watch 表示と CSV

```
23:03:49 [0x10] Δseq=  8  DP 1.23 Pa, Temp 24.50 °C
```

`Δseq` は前回からの sample_seq の進み。差圧センサ (125 ms 周期) なら 1 秒間隔で 8 前後になる。
PC と子機の時計がわずかにずれているため、ときどき 7 や 9 が出るのは正常。

CSV は子機ごとに別のファイル (`osl_YYYYMMDD_HHMMSS_0x10.csv` など)。BOM 付き UTF-8 で、Excel でそのまま開ける。

```
datetime,addr,device_id,name,model,result,sample_seq,delta_seq,value0,unit0,status0,value1,unit1,status1
```

- `status_i` はチャネルごとの状態 (BACnet Reliability の値)。0 なら正常、64 は準備中。
- 読み出しに失敗した回は `result` が `read_failed` の行になる。

### グラフ (--plot)

watch と同じ読み出しをしながらグラフのウィンドウを開く。子機ごとに 1 行、チャネルごとに 1 列。
状態が正常でない値と読み出し失敗は線が途切れる。描画のコードは `osl_plot.py`。

## osl_set.py — 設定を変える

```
python osl_set.py 0x10 --name "3F 会議室 天井"     名前を変える
python osl_set.py 0x10 --set dp_b=-0.12             ユーザー領域の値を変える (複数指定可)
python osl_set.py 0x10 --addr 0x11                  I2C アドレスを 0x11 に変える (確認あり)
python osl_set.py 0x10 --reset                      ソフトウェアリセット
python osl_set.py 0x10 --identify 10                識別表示 (LED のある機種のみ)
```

- 名前・ユーザー領域・アドレスは、子機が書き込みを受けた時点で EEPROM に保存する。
- アドレス変更の前に、新しいアドレスに別の機器がいないか確かめる (いれば中止)。変更後は
  新しいアドレスで同じ Device ID が応答することを確かめる。
- 新品の子機は既定のアドレス 0x10 で出荷されるので、1 台ずつつないでアドレスを変えること。
- CP2112 は 1 回の書き込みが 61 バイトまでなので、名前 (64 バイト) は 2 回に分けて書く。

## osl_v2_test.py — 適合試験

```
python osl_v2_test.py 0x10                      0x10 の子機を試験する
python osl_v2_test.py 0x10 --test-addr 0x11     アドレス変更も試す (0x11 に変えて 0x10 に戻す)
```

v2 の約束を一通り確かめ、合格・不合格を一覧で出す。名前とユーザー領域は試験の前の値に戻す。

| 試験 | 内容 |
|---|---|
| 安全な走査と識別 | 番地なしの読み出しで `"OSL"`、CRC、仕様版、チャネル数、device_id |
| 各区画の CRC | 名前、チャネル記述、拡張識別、拡張チャネル属性、拡張ステータス |
| 未実装・予約の番地 | 読むと 0 が返る |
| 読み取り専用 | 識別区画への書き込みが無視される |
| 読み出し位置の規則 | 番地だけ書いて STOP → 読むとその番地から返る、読み出しやデータ付き書き込みの後は 0x0000 |
| POLL | 2 秒間連続して読んでも CRC が合う、sample_seq が更新周期どおりに進む |
| 拡張ステータス | 稼働時間が進む |
| 名前 | UTF-8 の書き込みと読み戻し、CRC の作り直し、63 バイトの上限 |
| ユーザー領域 | 値の書き込みと読み戻し |
| リセット | 稼働時間の巻き戻り、起動要因 = ソフトウェア、名前とユーザー領域の保持 |
| アドレス変更 | 鍵が無ければ変わらない、鍵付きで変わる、旧アドレスは応答しない、元に戻す |

## dump_memory.py — 16 進ダンプ

```
python dump_memory.py 0x10                    0x0000 から 0x60 バイト
python dump_memory.py 0x10 0x0300 0x20        番地 0x0300 (POLL) から 0x20 バイト
python dump_memory.py 0x10 --noaddr 0x20      番地を送らずに読む (読み出し位置の確認用)
```

## 困ったとき

| 症状 | 確認すること |
|---|---|
| `USB-I2C ブリッジが見つかりません` | USB の接続。デバイスマネージャーで「USB 入力デバイス」として見えているか |
| `OSL v2 子機が見つかりません` | 配線、プルアップ抵抗、子機の電源、子機のファームウェアが v2 か。`python mcp2221_driver.py` で SCL / SDA が 1 になっているか |
| `OSL 子機ではない` | 相手が OSL 子機でないか、v1 のファームウェアのまま |
| `CRC 不一致` が続く | 配線が長すぎる・ノイズ。速度を落とす、プルアップ抵抗を見直す |
| SCL または SDA が 0 | プルアップ抵抗が無いか、子機が SCL/SDA を Low に張り付かせている。子機の電源を入れ直す |
| 応答がおかしい・止まる | 他のソフト (MCP2221 Utility など) が同じ MCP2221 を開いていないか |

MCP2221 は、電源投入後に一度も I2C を使っていない状態で転送キャンセルを受けると、内部状態 0x62 に
落ちて戻らなくなる。ドライバはこれを避けているうえ、万一固まった場合はチップを自動でリセットする
(USB の再接続が起きるので 2 秒ほど待たされる)。
